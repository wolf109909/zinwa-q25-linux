# Zinwa Q25 MT6789 native connectivity on Linux 7.3.3

On `7.3.3-cachyos-q25`, both LTE data (`ccmni0`) and CONNSYS Wi-Fi/Bluetooth work without an Android LXC container. The cellular modem is MD1 Gen97 `MOLY.LR13.R2.MP.V85.3`.

## Native LTE bring-up

Load modules in this order: `ccci_util_lib.ko` → `ccmni.ko` → `rps_perf.ko` → `ccci_md_all.ko` → `ccci_auxadc.ko` → `ccci_rtc.ko` → `ccci_ccif.ko` → `ccci_dpmaif.ko` → `ccci_fsm_scp.ko` → `conn_md_drv.ko`.

Required kernel/DT support: `ccci_util_lib_fo.c` reads LK’s `/chosen` (`atag,mdinfo`, `ccci,modem_info_v2`) and `/soc/mddriver` (`ccci,modem_info_v2`); `ccci_util_lib_reserved_mem.c` falls back to `ioremap_wc()` when `vmap_reserved_mem()` fails on `no-map` regions `0x90000000` / `0x9c000000`. DT needs `/soc/mddriver` with `md_vmodem-supply` and `md_vsram-supply`, `/soc/ccifdriver@10209000`, and `/soc/dpmaifdriver@1022d000`.

Create `/dev/block/by-name/<PARTNAME>` and `/dev/block/platform/bootdevice/by-name/<PARTNAME>` from `/sys/block/sdc/sdc*/uevent` (`PARTNAME=`), plus `/dev/block/by-name/preloader_raw_a -> /dev/sdc1`. Mount `/mnt/vendor/nvdata` (`/dev/sdc34`), `/mnt/vendor/nvcfg` (`/dev/sdc30`), `/mnt/vendor/protect_f` (`/dev/sdc31`), `/mnt/vendor/protect_s` (`/dev/sdc32`), `/mnt/vendor/persist` (`/dev/sdc29`), and `/vendor` from `super` (`/dev/sdc59`, sector offset `9177088 * 512`). Mount `system_a` at sector offset `5302272 * 512` for `/system/lib64/libhardware_legacy.so` and `/apex/com.android.runtime/bin/linker64`.

`userspace/sbin/libprop_preload.so` shims `__system_property_get`, `__system_property_set`, `__system_property_find`, `__system_property_read_callback`, and `__android_log_buf_write` using `/tmp/mtk_props/<name>`. Pre-populate `ro.vendor.mtk_md_sbp_custom_value=0`, `vendor.service.nvram_restore=Ready`, and `ril.telephony.mode=0`. Run with `LD_PRELOAD=/tmp/libprop_preload.so`: `/vendor/bin/nvram_daemon`, `/vendor/bin/ccci_fsd 0`, `/vendor/bin/ccci_rpcd`, `/vendor/bin/ccci_mdinit 0`, and optionally `/vendor/bin/gsm0710muxd -s /dev/ttyC0 -f 512 -n 8 -m basic`. Otherwise use `/dev/ttyC0` directly. Allow ~12s after `ccci_mdinit`; verify `cat /sys/kernel/ccci/boot` shows `md1:4` and `/tmp/mtk_props/vendor.mtk.md1.status` is `ready`.

AT setup on `/dev/ttyC0`:
```text
AT+CMEE=1
AT+CREG=2
AT+CGREG=2
AT+CEREG=3
AT+EREGINFO=1
AT+EIMS=1
AT+ECFGSET="mtk_ct_volte_support","1"
AT+EGTYPE=4
AT+EAPNLOCK=1
AT+EAPNSET="",1,"",""
AT+EAPNSET="ctnet",2,"type=default,supl;protocol=IPV4V6;roaming_protocol=IPV4V6;authtype=0;carrier_enabled=1;max_conns=0;max_conns_time=0;wait_time=0;bearer_bitmask=0;inactive_timer=0"
AT+EAPNSET="ims",2,"type=ims;protocol=IPV4V6;roaming_protocol=IPV4V6;authtype=0;carrier_enabled=1;max_conns=0;max_conns_time=0;wait_time=0;bearer_bitmask=0;inactive_timer=0"
AT+EAPNLOCK=0
AT+ECNCFG=1,,,1,1,1
AT+EIAAPN="ctnet",0,"IPV4V6","IPV4V6",0,"",""
AT+EIAREG=1
AT+EDALLOW=1
AT+EFUN=1
AT+COPS=0
```
After registration (`+CEREG: 1,...` or `+CEREG: 5,...`), activate and complete the NetAgent/LHIF handshake:
```text
AT+EAPNACT=1,"ctnet","default",0
AT+EPDN=0,"ifst",20
AT+EIF=100, "ifst", "up", 3
AT+EAPNACT=3,0
```
The modem emits `+EIF: 100, ifup, 3, <IPv4>, <IPv6_LL>, 0` and `+CGEV: ME PDN ACT 0`. Query DNS with `AT+CGCONTRDP` and IP with `AT+EPDN=0,"addr"`; configure the interface:
```sh
ip addr flush dev ccmni0
ip addr add <IPv4>/24 dev ccmni0
ip link set ccmni0 up
ip route replace default dev ccmni0 metric 200
```

## Native Wi-Fi and Bluetooth

CONNSYS is MT6631 at `0x18000000`; reserved EMI is `0x7e000000` (size `0x500000`) and shared DMA pool is `0xbf000000` (size `0x600000`). Wi-Fi interfaces `wlan0`, `wlan1`, `p2p0`, `ap0` and Bluetooth 5.4 (`hci0`, BR/EDR + BLE) work natively. Relevant modules include `btif_drv.ko`, `conn_md_drv.ko`, `connadp.ko`, `connfem.ko`, `wmt_drv.ko`, `wmt_chrdev_wifi.ko`, `wlan_drv_gen4m_6789.ko`, and `bt_drv_connac1x.ko`.

WMT ROM-patch configuration in `wmt_ctrl_get_rom_patch_info()` maps ADIE `0x6635` to flavor `1e_1` and `0x6631` to `1d_1`; use `soc2_2_ram_bt_<flav>_hdr.bin`, `soc2_2_ram_wifi_<flav>_hdr.bin`, and `soc2_2_ram_mcu_<flav>_hdr.bin` at EMI offsets `0x170000`, `0x2a0000`, and `0x000000`. `wmt_ctrl_update_patch_version()` returns `0`; keep `gWmtClose = 0` in `WMT_close()`. `STP_BTIF_FULL` is `0x03`, so `WMT_IOCTL_SET_STP_MODE` uses `0x23` (`STP_BTIF_FULL (3) | (WMT_FM_I2C (2) << 4)`).

`userspace/sbin/q25-wmt-init.c` initializes CONNSYS through `/dev/wmtdetect`, sets STP mode on `/dev/stpwmt`, loads `/lib/firmware/WIFI` into `/dev/wmtWifi`, and registers Wi-Fi interfaces. `glLoadNvram()` has a `kalRequestFirmware("WIFI", ...)` fallback. `wlanProbe` refreshes `gConEmiPhyBaseFinal` and `gConEmiSizeFinal` from the base values when unset. `userspace/sbin/q25-bt-vhci.c` bridges `/dev/stpbt` to `/dev/vhci`, sets the factory BD_ADDR from `/lib/firmware/BT_Addr` using vendor HCI `0xFC1A`, and synthesizes Command Complete responses for `0x0c77`, `0x100b`, and `0x100d`.

### CONNSYS + MD1 coexistence fix

For simultaneous Wi-Fi + Bluetooth + 4G LTE on Zinwa Q25 (`MT6789` / `MT6631`, Mainline Linux `7.3.3-cachyos-q25`), define `CONFIG_MTK_ECCCI_DRIVER_MODULE 1` and `CONFIG_MTK_ECCCI_C2K 1` in `drivers/include/linux/q25_compat.h`; load `ccci_md_all.ko` before `wmt_drv.ko`.

In `drivers/mediatek/connectivity/common/common_main/platform/mt6789.c`, `consys_emi_restore_dump_mt6789()` checks `#if defined(CONFIG_MTK_ECCCI_DRIVER) || defined(CONFIG_MTK_ECCCI_DRIVER_MODULE)` before calling `get_smem_phy_start_addr(MD_SYS1, SMEM_USER_RAW_MD_CONSYS, &size)` and programming `CONSYS_EMI_AP2MD_OFFSET` (`0x1800239c` = `0x00008d60`). In `drivers/mediatek/connectivity/common/common_main/linux/wmt_dev.c`, `CFG_WMT_LTE_COEX_HANDLING` requires `CONFIG_MTK_ECCCI_C2K` to be defined so `wmt_idc_init()` registers the `conn_md` bridge callbacks for `PCCIF4`.

When building out-of-tree (`M=drivers/mediatek`), neither macro is in the kernel `.config`; `MD_MAPPING` remains unprogrammed (`0x0`) and `conn_md` drops LTE coexistence messages, crashing MD1 (`MCU_core0,vpe0,tc0(VPE0) EL1 [0x00000305, 0x888802FC]`) ~10s after boot whenever CONNSYS is powered on.

### Linux 7.3.3 net_device dev_addr fix

Mainline Linux 7.3.3 maintains `dev->dev_addrs` rb-tree and checks `dev_addr_check()` on `dev_open()`. Direct `kalMemCopy(prDev->dev_addr, ...)` in `gl_init.c`, `gl_kal.c`, `gl_p2p.c`, `gl_p2p_init.c`, `gl_nan.c`, and `gl_bow.c` left `wlan0` with `00:00:00:00:00:00` in `dev->dev_addrs`, logging `wlan0: Incorrect netdev->dev_addr` and `NO-CARRIER`. Replace these copies with `__dev_addr_set(prDev, mac, ETH_ALEN)` to give `wlan0` its clean factory MAC (`00:08:22:ec:80:fc`). Direct `memset(dev->dev_addr, ...)` in `drivers/mediatek/ccmni/ccmni.c` corrupts `ccmni0` after `eth_hw_addr_random(dev)`; remove the direct `dev_addr` write to fix `ccmni0`.
