Authoritative MediaTek MT6789 DRM/DSI display pipeline details (from `LineageOS/android_kernel_xelex_mt6789` `drivers/gpu/drm/mediatek/mediatek_v2/platform/mtk_drm_6789.{c,h}` and live Q25 hardware state):

1. **DSI0 (`0x14013000`, `mediatek,mt6789-dsi`)**:
   - `.reg_cmdq_off = 0xd00`, `.reg_vm_cmd_off = 0x200`, `.reg_shadow_dbg_off = 0x190` (`DSI_SHADOW_DEBUG = 0x190`, `FORCE_COMMIT | BYPASS_SHADOW = 0x6`), `.has_shadow_ctl = true`, `.has_size_ctl = true`, `.cmdq_long_packet_ctl = true`, `.support_per_frame_lp = true`.
   - Bootloader leaves `DSI_START = 1` (Video Mode active) and `DSI_INTSTA (0x0c) = 0x80000792` (`CMD_DONE_INT_FLAG | DSI_BUSY` asserted). Do NOT enable `DSI_INTEN` when keeping active Video Mode without clearing `DSI_INTSTA`, and bound the `while (tmp & DSI_BUSY)` loop in `mtk_dsi_irq()`, otherwise IRQ 301 spins forever in hard-IRQ context because `DSI_BUSY` (`BIT(31)`) stays asserted during Video Mode scanout.

2. **OVL0 (`0x14005000`, `mediatek,mt6789-disp-ovl`)**:
   - Uses `DISP_REG_OVL_ADDR_MT8173` (`0x0f40`), `.gmc_bits = 10`, `.layer_nr = 4`, `.fmt_rgb565_is_0 = true`, `.smi_id_en = true`.
   - Requires `DISP_OVL_BYPASS_SHADOW` (`BIT(22) = 0x00400000`) in `DISP_REG_OVL_EN` (`0x000c`), so `mtk_ovl_start()` must write `0x1 | BIT(22)` (`0x00400001`), NOT `0x1`.
   - `DISP_REG_OVL_DATAPATH_CON` (`0x0024`) requires `OVL_LAYER_SMI_ID_EN | BIT(24) | BIT(26)` (`0x05000001`) and `OVL_BGCLR_SEL_IN` (`BIT(2)`) cleared when `OVL0` is the primary blender (`0xf04 = 0x1`).
   - Clear `DISP_REG_OVL_SRC_CON` (`0x002c`) in probe to disable bootloader's leftover `L1` layer (`L1_ADDR = 0`).

3. **RDMA0 (`0x14007000`, `mediatek,mt6789-disp-rdma`)**:
   - `mediatek,rdma-fifo-size = <48992>` (`0xbf6 * 16`).
   - In Video Mode, `RDMA_OUTPUT_VALID_FIFO_THRESHOLD` in `DISP_REG_RDMA_FIFO_CON` (`0x0040`) must be `0` (`0x8bf60000`).
   - `DISP_REG_RDMA_SHADOW_UPDATE` (`0x00bc`) requires `0x6` (`FORCE_COMMIT | BYPASS_SHADOW`).

4. **MMSYS (`0x14000000`, `mediatek,mt6789-mmsys`) & DISP_MUTEX (`0x14001000`, `mediatek,mt6789-disp-mutex`)**:
   - `MT6789_MMSYS_OVL_CON (0xf04) = 0x1` (`OVL0_GO_BLEND`, clearing `OVL0_2L_GO_BG = BIT(3)`).
   - `MT6789_DISP_TOVL0_OUT0_MOUT_EN (0xf14) = 0x0`, `MT6789_DISP_TOVL0_OUT1_MOUT_EN (0xf18) = 0x1` (`OVL0 -> RDMA0`), `MT6789_DISP_RDMA0_SEL_IN (0xf28) = 0x0`.
   - Downstream active relay chain (`RDMA0 -> COLOR0 -> CCORR0 -> AAL0 -> GAMMA0 -> POSTMASK0 -> DITHER0 -> DSI0`) uses `0xf0c = 0x1`, `0xf20 = 0x1`, `0xf30 = 0x1` (or direct `RDMA0 -> DSI0` uses `0xf0c = 0x0`, `0xf20 = 0x0`, `0xf30 = 0x0`).
   - `MUTEX0_MOD0` (`0x30`) bits: `OVL0=0`, `OVL0_2L=1`, `RDMA0=2`, `RSZ0=3`, `COLOR0=4`, `CCORR0=5`, `AAL0=7`, `GAMMA0=8`, `POSTMASK0=9`, `DITHER0=10`, `DSC0=13`, `DSI0=14`, `WDMA0=15`, `PWM0=16`. `MUTEX0_SOF0` (`0x2c`) = `0x41` (`SOF_DSI0 | EOF_DSI0`).
   - Do not enable `larb0`/`larb1` in DT without `mm_iommu`, as `mtk_smi_larb_config_port_gen2_general()` dereferences `larb->mmu` (`NULL` when no IOMMU is bound). Bootloader leaves `LARB0`/`LARB1` `NON_SEC_CON` at `0` (physical 32-bit DMA mode).
