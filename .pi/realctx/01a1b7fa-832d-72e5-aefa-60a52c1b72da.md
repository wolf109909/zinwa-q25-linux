On Zinwa Q25 (`MT6789`, Mainline Linux `7.3.3-cachyos-q25`), `drivers/keyboard/bbqX0kbd_main.c` (`bbqX0kbd.ko`) registers standard LED class devices and `/proc` controls:
- **Keyboard backlight**: `/sys/class/leds/q25:white:kbd_backlight/brightness` (`0-255`) and `/proc/q20_kbd_brightness` (`REG_BKL = 0x05` on I2C6 `0x1f`).
- **Torch / Flashlight**: `/sys/class/leds/q25:white:torch/brightness` (`0` = off, `1` = torch, `2` = high/flash) and `/proc/q20_torch` (MT6789 pinctrl GPIO `154` = enable, `155` = mode, resolved via `gpio_device_find_by_fwnode()` on `"mediatek,mt6789-pinctrl"`).
- **Vibrator / Haptics**: `/sys/class/leds/q25:vibrator/brightness` (`0`/`1`) and `/proc/q20_vibrator` (`0` = off, `1` = continuous on, `2..5000` = timed pulse in milliseconds, using `regulator_get_optional(NULL, "vibr")` for the MT6358 `vibr` 2.8V LDO).
- **Trackpad key/mouse mode**: `/proc/q20_switch_key_mouse`; `q20_spec_switch_key_mouse == 0` = Mouse Pointer mode (`REL_X`/`REL_Y`, `keycode[0x05] = BTN_LEFT`), `1` = Arrow Keys mode (`KEY_UP`/`DOWN`/`LEFT`/`RIGHT`, `keycode[0x05] = KEY_ENTER`). `RightShift + T` toggles the mode and updates `keycode[0x05]` in `bbqX0kbd_work_fnc`. Do not intercept `RIGHT_ALT_BIT` (`Sym`) in the kernel so `keyd` `[ralt_sym_layer2]` receives all `Sym + <key>` combinations intact.
- **IRQ deadlock fix**: `devm_request_threaded_irq(..., NULL, bbqX0kbd_irq_handler, IRQF_SHARED | IRQF_ONESHOT, ...)` already masks the IRQ until the threaded handler returns. Calling `disable_irq_nosync(client->irq)` in `bbqX0kbd_irq_handler` and `enable_irq()` in scheduled work caused `disable_depth` imbalance and could permanently lock up the keyboard/trackpad when two interrupts arrived before `work_fnc` ran or `REG_INT_OVERFLOW` (`0x01`) fired without `REG_INT_KEY`/`REG_INT_TOUCH`. Process `bbqX0kbd_work_fnc` directly inside the `IRQF_ONESHOT` threaded IRQ handler, without `disable_irq_nosync`/`enable_irq`, so `REG_INT` is always cleared to `0x00`.
- **Berry / Menu key**: In `drivers/keyboard/bbq20kbd_pmod_codes.h`, map scancode `[0x11]` to `KEY_LEFTMETA` (`125`), not `580` (`0x244 = KEY_APPSELECT`), because `keyd` rejects evdev keycodes `>= 256` (`ERROR: unsupported evdev code: 0x244`).
