On Zinwa Q25 (`MT6789`, Mainline Linux `7.3.3-cachyos-q25`):
1. **Volume Down is `GPIO 66` (`PINMUX_GPIO66__FUNC_KPCOL0`), NOT `GPIO 43`:**
   - Configuring `gpio-keys` on `GPIO 43` with `GPIO_ACTIVE_LOW` caused `KEY_VOLUMEDOWN` to stay permanently asserted (`EVIOCGKEY` bit set), which made `keyd`'s `wait_for_keyboard_neutral()` loop at 100% CPU forever on startup without creating `keyd virtual keyboard` or `keyd virtual pointer`.
   - Using `gpios = <&pio 66 (GPIO_ACTIVE_LOW | GPIO_PULL_UP)>;` in `devicetree/mt8781-zinwa-q25.dts` fixes Volume Down and lets `keyd` attach immediately to `Q25_keyboard`, `gpio-keys`, and `mtk-pmic-keys`.
2. **Flattened Pure Arch Linux ARM Rootfs (`/dev/mapper/q25-q25--rootfs` -> `/rootfs`):**
   - Arch Linux ARM now lives directly at the root of `/dev/mapper/q25-q25--rootfs` (`/rootfs/usr`, `/rootfs/etc`, etc.) with no `/opt/arch` subdirectory or duplicate `arch-*.desktop` launcher entries.
   - `userspace/sbin/q25-modem-init` checks `[ ! -f /etc/arch-release ]` before `exec chroot /rootfs /usr/local/sbin/q25-modem-init "$@"` to avoid recursive chroot loops.
   - `userspace/bin/q25-control-center` uses `ip -4 addr show dev <ifname>` (not `ip -4 -br addr`, which BusyBox `ip` rejects) and `Gdk.ModifierType` (not `GLib.ModifierType`), preventing Mobile Data from auto-disabling on the 6-second UI refresh.
3. **GCC 16.2.0 `__builtin_counted_by_ref` `tty_buffer` Workaround (`q25-terminal`):**
   - `aarch64-linux-gnu-gcc` 16.2.0 mis-evaluates `_Generic(__builtin_counted_by_ref(p->data), void *: ...)` in `kmalloc_flex(struct tty_buffer, data, size)`, leaving `tb->size = 0` so `devpts` PTY writes return `0` and `foot` child shells spin in `fflush()`.
   - `userspace/bin/q25-terminal` provides a native GTK4/Libadwaita Wayland terminal (`org.zinwa.Q25Terminal`) using `subprocess.PIPE` (independent of `devpts`), wired to `foot.desktop` and `q25-control-center`.
