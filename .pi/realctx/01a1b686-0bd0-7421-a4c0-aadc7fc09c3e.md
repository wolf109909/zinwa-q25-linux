On Zinwa Q25 (`MT6789`, Android Boot Image v3 + Vendor Boot v3), LK places `vendor_boot_a`'s `0x120c19f`-byte vendor ramdisk at `0x66f00000..0x6810c19f`, then appends `boot_a`'s ramdisk. Linux unpacks the vendor CPIO first and the `boot_a` CPIO second, so the vendor archive's 16-byte `init -> /system/bin/init` symlink can overwrite `/init` unless the `boot_a` archive replaces it. In `mt8781-zinwa-q25.dts`, set `linux,initrd-start = <0 0x66f00000>;` and `linux,initrd-end = <0 (0x66f00000 + 0x120c19f + len(ramdisk_payload))>;` (equivalently `0x6810c19f + len(ramdisk_payload)`). Omitting `0x120c19f` truncates the initrd before the appended `boot_a` ramdisk; the kernel then unpacks only the vendor ramdisk, whose Android `/init` can fail with `libkeyutils.so` missing and `Attempted to kill init!`. The vendor archive also supplies stock Android 5.10 modules under `/lib/modules/*.ko`; the `boot_a` initramfs (`initramfs-7.3-q25.cpio.gz`) adds 7.3.3 modules under `/lib/modules/7.3.3-cachyos-q25.../updates/q25/*.ko`. In `/init`, run `rm -f /lib/modules/*.ko` to remove the stock modules. Before packing `/tmp/boot-7.3.3-cachyos-q25-v23.img`, rebuild `/tmp/initramfs-7.3-q25.cpio.gz` (not `/tmp/q25-initramfs-7.3.cpio.gz`).
