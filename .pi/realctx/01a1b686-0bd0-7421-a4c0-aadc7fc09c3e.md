On Zinwa Q25 (`MT6789`), the LK bootloader loads `vendor_boot_a`'s vendor ramdisk (`18,923,935` bytes = `0x120c19f`, `/tmp/q25_vendor_ramdisk.bin`) first at `0x66f00000..0x6810c19f`, and appends `boot_a`'s ramdisk (`ramdisk_size`) immediately after it at `0x6810c19f`.

Therefore, in `mt8781-zinwa-q25.dts`:
- `linux,initrd-start = <0 0x66f00000>;`
- `linux,initrd-end = <0 (0x66f00000 + 0x120c19f + len(ramdisk_payload))>;` (i.e. `0x6810c19f + len(ramdisk_payload)`).

If `linux,initrd-end` is set to `0x66f00000 + len(ramdisk_payload)` without adding `0x120c19f`, the kernel truncates initrd before `0x6810c19f`, unpacking only `vendor_boot_a`'s ramdisk (Android `/init`, which fails with `libkeyutils.so` missing and `Attempted to kill init!`).
