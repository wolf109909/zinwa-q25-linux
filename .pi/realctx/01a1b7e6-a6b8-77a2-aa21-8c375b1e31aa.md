On Zinwa Q25 (`MT6789` + `MT6358` + `OCA7255`, Mainline Linux `7.3.3-cachyos-q25`), the `ZinwaQ25Audio` ALSA card (`drivers/audio/q25_afe_pcm.c`, built into `snd-soc-oca72xxx.ko`) requires:
1. **SPM AUDIO MTCMOS Power Domain & Bus Protection**:
   - `spm` in `mt6789.dtsi` has no consumer on `MT6789_POWER_DOMAIN_AUDIO` because `11210000.syscon` (`clk-mt6789-audiosys`) has no `power-domains` property, so `mtk-pm-domains` powers off AUDIO during `late_initcall`.
   - `q25_afe_enable_clocks_and_pins()` must unlock SPM (`writel(0x0b160001, spm_base + 0x0000)`), power on `AUDIO_PWR_CON` (`0x10006358`: `PWR_ON` bit 2, `PWR_ON_2ND` bit 3, poll `PWR_STATUS` `0x16c`/`0x170` bit 22, clear `PWR_CLK_DIS` bit 4 and `PWR_ISO` bit 1, set `PWR_RST_B` bit 0, clear `SRAM_PDN` bit 8 and wait `SRAM_PDN_ACK` bit 12 == 0), and clear `INFRACFG_AO` `TOP_AXI_PROT_EN_2_CLR` (`0x10001718` bit 4).
2. **MT6789 Clock Gate Offsets**:
   - `INFRACFG_AO`: `MODULE_SW_CG_1_CLR` is `0x008c` (bit 25 = `ifrao_audio`), `MODULE_SW_CG_2_CLR` is `0x00a8` (bit 4 = `ifrao_audio26m`). Writing `0x0088` (`MODULE_SW_CG_1_SET`) gates `ifrao_audio` and makes all AFE register reads return `0`.
   - `TOPCKGEN`: `CLK_CFG_7_CLR` (`0x0088` bit 31 = `audio_sel`), `CLK_CFG_8_CLR` (`0x0098` bit 7 = `aud_intbus_sel`), `CLK_CFG_12_CLR` (`0x00d8` bits 7, 15 = `aud_engen1/2_sel`), `CLK_CFG_13_CLR` (`0x00e8` bits 7, 15 = `aud_1/2_sel`), `CLK_CFG_15_CLR` (`0x0108` bit 7 = `audio_h_sel`), committed via `CLK_CFG_UPDATE1` (`0x0008`).
3. **MT6789 Audio SRAM Physical Address**:
   - Audio SRAM starts at `0x11212000` (size `0xd000` = 52 KiB, node `audio_sram@11212000`), NOT `0x11211000` (`0x11210000..0x11211fff` is the 8 KiB AFE register file). Setting `AFE_DL1_BASE` to `0x11211000` causes DL1 DMA (`AFE_DL1_CUR`) to freeze and IRQ0 to never fire.
   - Use `vmalloc_user` shadow buffers for both playback and capture with `remap_vmalloc_range` in `.mmap` so userspace ALSA/PipeWire can safely do unaligned accesses without triggering arm64 Device-memory alignment faults.
