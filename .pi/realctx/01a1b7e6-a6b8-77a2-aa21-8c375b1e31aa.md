On Zinwa Q25 (`MT6789` + `MT6358`/`MT6366` + `OCA7255`/`oca72390` at I2C `3-0058`), Mainline Linux `7.3.3-cachyos-q25`, the `ZinwaQ25Audio` ALSA card (`drivers/audio/q25_afe_pcm.c`, built into `snd-soc-oca72xxx.ko`) requires:

- **SPM AUDIO power domain and bus protection:** `spm` in `mt6789.dtsi` has no consumer on `MT6789_POWER_DOMAIN_AUDIO` because `11210000.syscon` (`clk-mt6789-audiosys`) lacks `power-domains`; `mtk-pm-domains` therefore powers AUDIO off during `late_initcall`. In `q25_afe_enable_clocks_and_pins()`, unlock SPM (`writel(0x0b160001, spm_base + 0x0000)`), power on `AUDIO_PWR_CON` (`0x10006358`: set `PWR_ON` bit 2 and `PWR_ON_2ND` bit 3; poll `PWR_STATUS` `0x16c`/`0x170` bit 22; clear `PWR_CLK_DIS` bit 4 and `PWR_ISO` bit 1; set `PWR_RST_B` bit 0; clear `SRAM_PDN` bit 8 and wait for `SRAM_PDN_ACK` bit 12 == 0), and clear `INFRACFG_AO` `TOP_AXI_PROT_EN_2_CLR` (`0x10001718` bit 4).
- **Clock gates:** `INFRACFG_AO` `MODULE_SW_CG_1_CLR` is `0x008c` (bit 25 `ifrao_audio`); `MODULE_SW_CG_2_CLR` is `0x00a8` (bit 4 `ifrao_audio26m`). Writing `0x0088` (`MODULE_SW_CG_1_SET`) gates `ifrao_audio`, making AFE reads return `0`. `TOPCKGEN` selectors: `CLK_CFG_7_CLR` (`0x0088`, bit 31 `audio_sel`), `CLK_CFG_8_CLR` (`0x0098`, bit 7 `aud_intbus_sel`), `CLK_CFG_12_CLR` (`0x00d8`, bits 7 and 15 `aud_engen1/2_sel`), `CLK_CFG_13_CLR` (`0x00e8`, bits 7 and 15 `aud_1/2_sel`), and `CLK_CFG_15_CLR` (`0x0108`, bit 7 `audio_h_sel`); commit via `CLK_CFG_UPDATE1` (`0x0008`).
- **Audio SRAM and userspace buffers:** SRAM starts at `0x11212000`, size `0xd000` (52 KiB, node `audio_sram@11212000`), not `0x11211000` (`0x11210000..0x11211fff` is the 8 KiB AFE register file). Using `0x11211000` for `AFE_DL1_BASE` freezes DL1 DMA (`AFE_DL1_CUR`) and prevents IRQ0. Use `vmalloc_user` shadow buffers for playback and capture, with `remap_vmalloc_range` in `.mmap`, to avoid arm64 Device-memory alignment faults on unaligned userspace ALSA/PipeWire accesses.
- **ADDA controls:** On MT6789, `AFE_ADDA_DL_SRC2_CON0` (`0x0108`) uses `BIT(12)` (`DL_2_MUTE_CH1_OFF_CTL_PRE`) and `BIT(11)` (`DL_2_MUTE_CH2_OFF_CTL_PRE`) to unmute CH1/CH2. Setting `BIT(4) | BIT(3)` (`D2_2_MUTE_CH1/CH2_ON_CTL_PRE`) mutes the ADDA DL interpolator (`AFE_ADDA_DL_SRC_LCH_MON` / `RCH_MON` stay `0x00000000`). `AFE_ADDA_UL_DL_CON0` (`0x0124`) resets to `0x60006000` (`AFE_ADDA_CKDIV_RST` bit 30 and `AFE_ADDA_FIFO_AUTO_RST_EN` bit 29 set); clear these before starting ADDA DL/UL. `AFE_ADDA_DL_SDM_AUTO_RESET_CON` is at offset `0x0c74`, not `0x0c78` (`AFE_CONNSYS_I2S_CON`). In `q25_afe_configure_adda_dl()`, set `AFE_ADDA_DL_SDM_DCCOMP_CON` (`0x0d1c`) to `0x1d` (`AUDIO_SDM_LEVEL_NORMAL`) and `AFE_ADDA_DL_SDM_AUTO_RESET_CON` (`0x0d40`) to `0x190000 | BIT(28) | BIT(31)` (`USE_NEW_2ND_SDM = BIT(28)`).
- **MT6358 register offsets:** Mainline Linux 7.3 `sound/soc/codecs/mt6358.h` defines `MT6358_AUDDEC_ANA_CON0..15` at `0x2408..0x2426`, not the `0x2080..0x209e` addresses used by older MT6358 variants. It defines `MT6358_ZCD_CON0..5` at `0x2488..0x2492`, `MT6358_AUDENC_ANA_CON6` at `0x2394`, `MT6358_DCXO_CW14` at `0x07ac`, and `MT6358_GPIO_MODE2` at `0x00d8`.
- **Lineout setup and routing:** Mainline `mt6358.c` defines `LOL Mux` as a plain `SND_SOC_DAPM_MUX`, without `mt_lo_event` or a route to `DL Power Supply`. Thus `q25_mt6358_lineout_amp_set()` must explicitly program playback `GPIO_MODE2` (`0x00d8 = 0x0249`), `DCXO_CW14` (`0x07ac` bit 13), `AUDGLB` (`0x2422` bit 4 = 0), `CLKSQ` (`0x2394` bit 0 = 1), `AUD_TOP_CKPDN_CON0` (`0x220c`), `AUDIO_TOP_CON0` (`0x2292`), `AFUNC_AUD_CON0/2` (`0x2296`/`0x229a`), `AFE_UL_DL_CON0` (`0x2288`), `AFE_DL_SRC2_CON0_L` (`0x228a`), `AUDNCP` (`0x223a..0x2242`), and `AUDDEC_ANA_CON0..15` (`0x2408..0x2426`). The OCA7255 2-in-1 speaker/receiver is driven from MT6358 `LINEOUT L` (`LOL`, `LO_MUX_L_DAC = 0x2 << 2` in `0x2416`); OCA72xxx profile `"Music"` drives full loudspeaker volume and `"Receiver"` attenuated earpiece volume.
